# AGENTS.md

Guide for AI coding agents (and humans) working in this repo. `CLAUDE.md` is a symlink to this file.

## What this is

**AI First Events**: a small events + RSVP app used in a hands-on workshop. Attendees add features
with AI coding agents. Favor clear, boring code over clever code.

- `/` upcoming events · `/events/[id]` detail + RSVP form · `/admin` all events with RSVP counts
- RSVP saves the attendee, emails a confirmation (Mailpit), and updates the count.
- Rules: full events reject RSVPs, duplicate email (case-insensitive) is rejected, past events reject RSVPs.

## Stack

| Path              | What                                                                            |
| ----------------- | ------------------------------------------------------------------------------- |
| `packages/shared` | zod schemas + TS types = the API contract, plus `ApiError` codes                |
| `packages/db`     | Drizzle schema, drizzle-kit migrations, `migrate.ts`, `seed.ts`, `reset.ts`     |
| `apps/api`        | Fastify API on :4000. Pure rules in `src/domain/rsvp-rules.ts`                  |
| `apps/web`        | Next.js 16 App Router + Tailwind 4 on :3000. Server components + server actions |
| `e2e`             | Playwright tests against the running stack                                      |
| `docs/goals`      | Feature cards for the workshop                                                  |

Node 22, pnpm 9 workspaces, TypeScript strict, ESLint (flat config) + Prettier at the root.
Postgres 16 on :5432, Mailpit UI/API on :8025 and SMTP on :1025.

Data flow: browser → Next.js (server components / server actions) → API → Postgres.
The browser never calls the API directly.

## Commands

```bash
make dev          # postgres + mailpit in Docker, api + web on the host with hot reload
make up           # whole stack in Docker (docker compose up --build)
make test         # lint + typecheck + unit + integration
make e2e          # docker compose up --build --wait, then Playwright
make seed         # add seed data to the dev DB
make reset        # drop dev DB, migrate, seed

pnpm lint | pnpm format | pnpm typecheck
pnpm test:unit                 # apps/api/test/unit (no services needed)
pnpm test:integration          # apps/api/test/integration (needs postgres + mailpit)
pnpm test:e2e                  # e2e/ (needs the app running on :3000)
pnpm db:generate               # create a migration after editing packages/db/src/schema.ts
pnpm db:migrate
```

Run one test file: `pnpm --filter @aifirst/api exec vitest run test/unit/rsvp-rules.test.ts`
or `pnpm --filter @aifirst/e2e exec playwright test tests/rsvp.spec.ts`.

## Rules

1. **Every feature ships with a test.** Business rules → unit test next to
   `test/unit/rsvp-rules.test.ts`. New/changed endpoints → integration test in
   `apps/api/test/integration`. New user-visible flows → Playwright spec in `e2e/tests`.
2. **Verify UI in the browser before saying you're done.** Use the Playwright MCP server
   (`.mcp.json`) to open http://localhost:3000, click through the feature, and check Mailpit at
   http://localhost:8025 when email is involved. Tests passing is not enough.
3. **Never hand-edit migrations.** Change `packages/db/src/schema.ts`, then run
   `pnpm db:generate`. Commit the generated SQL and `meta/` files as-is.
4. **Keep shared types in `packages/shared`.** Request/response shapes and error codes live there
   and are imported by both api and web. Don't redeclare them in an app.
5. Keep business rules pure (no I/O) in `apps/api/src/domain`; services do I/O, routes stay thin.
6. Errors: throw `new ApiError('CODE')` in the API; the error handler turns it into
   `{ error: { code, message, fieldErrors? } }` with the right HTTP status.
7. Run `make test` before finishing. Run `make e2e` when you touched the web app.

## Where things live

- API routes: `apps/api/src/routes/*.ts`, registered in `apps/api/src/app.ts`
- RSVP transaction (`SELECT ... FOR UPDATE` on the event row): `apps/api/src/services/rsvp-service.ts`
- Email: `apps/api/src/services/mailer.ts` (nodemailer → Mailpit)
- Web API client (server-only): `apps/web/src/lib/api.ts`
- RSVP server action: `apps/web/src/app/events/[id]/actions.ts`, form in `src/components/RsvpForm.tsx`
- Seed data (dates relative to now): `packages/db/src/seed.ts`

## Gotchas

- Integration tests use a separate `aifirst_test` database and reset seed data before each test.
  Seed ids are stable (1–5) because the reset restarts identities.
- E2E tests reset the dev DB seed and clear Mailpit before the run.
- Next.js 16 differs from older versions (`params` is a Promise, no `next lint`, Turbopack by
  default). `apps/web/AGENTS.md` is generated by `next dev` and points to the bundled docs in
  `node_modules/next/dist/docs/`.
- Pages fetch with `cache: 'no-store'` and are `force-dynamic`, so `next build` never needs the API.
